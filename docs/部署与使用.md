# 本地部署与使用

## 运行环境

- Windows 10/11，安装带 Tkinter 的 Python 3.8 或更新版本。Python 3.12 已通过回归测试。
- 可读取原稿和副本，合稿保存目录可写入。
- 审阅合稿时可使用 Microsoft Word 或兼容 DOCX 的文档程序。

部署基础合并功能需要 Python 包 lxml 和 Pillow。使用离线安装包时，依赖文件应与主程序安装包一起准备。

## 从源码安装

在 PowerShell 中进入项目目录，创建虚拟环境并安装项目：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install .
```

如果安装了多个 Python，请将第一条命令中的 `python` 替换成所需解释器的完整路径。此后使用同一个虚拟环境执行命令。

## 从 wheel 安装

在保存 wheel 的目录中创建虚拟环境，然后安装主程序：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\mddm_document_merger-1.0.0-py3-none-any.whl
```

若已经准备包含主程序和依赖的离线目录，使用：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\wheelhouse mddm-document-merger==1.0.0
```

Windows 离线依赖 wheel 需要与目标计算机的 Python 版本和架构一致。Tkinter 由 Python 安装程序提供，应在安装 Python 时选择 Tcl/Tk 组件。

## 启动桌面界面

从项目目录运行：

```powershell
.\.venv\Scripts\pythonw.exe -m mddm.merge_gui
```

界面中依次选择原稿、存放部门副本的目录和合稿保存位置，点击“开始合并”。任务结束后可打开合稿、冲突报告和变更日志。

也可在已激活虚拟环境后运行 `mddm-gui`。

## 命令行合并

```powershell
.\.venv\Scripts\python.exe -m mddm.run_merge "C:\工作\周报原稿.docx" "C:\工作\部门副本" -o "C:\工作\输出\部门周报合稿.docx"
```

查看参数说明：

```powershell
.\.venv\Scripts\python.exe -m mddm.run_merge --help
```

原稿作为共同基准，副本目录存放各部门从该原稿编辑的 DOCX 文件。建议将合稿放在副本目录外。程序在合稿同目录生成 `_conflicts.txt` 冲突报告和 `_merged_changes_log.txt` 变更日志。

## 附加工具

`python -m mddm.process_headings --help` 查看标题处理参数。标题后处理可通过合并命令的 `--auto-fix-headings` 开启。

`python -m mddm.run_convert_formulas --help` 查看公式转换参数。MathType 二进制公式转换还需安装 Ruby 及 `mathtype_to_mathml_plus`，相关 OCR 模式需要单独安装对应可选依赖。

## 功能范围

桌面界面提供默认文档合并流程。命令行中的文本校对和图片编号选项依赖缺失的 `ai_heading_analyzer` 模块，当前不可用。项目目前仍有多段落表格单元格及文末新增段落的已知问题，请在复核合稿时检查这些位置。

## 验证部署

源码目录执行以下命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m mddm.run_merge --help
```

再用一份原稿和一个部门副本试运行，检查合稿和两个文本报告。涉及同一段落的竞争修改时，应根据冲突报告和作者批注核对结果。
